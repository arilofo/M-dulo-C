note as Proposito
  Propósito del patrón Observer

  Define una dependencia 1 a N entre objetos.
  Cuando el Subject cambia de estado,
  todos sus observadores son notificados
  automáticamente.

  En el Módulo C se aplica para automatizar:
  - La recepción de mercadería.
  - El registro de facturas de proveedor.
  - El envío de datos para retención.
  - La generación automática de cuentas por pagar.
end note

package "Flujo A: Recepción de Mercadería" {

  class Recepcion <<Subject>> {
    - observadores: List<ObservadorRecepcion>
    --
    + registrarRecepcion()
    + validarRecepcion()
    + marcarInventarioNotificado()
    + agregarObservador(obs: ObservadorRecepcion)
    + eliminarObservador(obs: ObservadorRecepcion)
    + notificarObservadores()
  }

  interface ObservadorRecepcion <<Observer>> {
    --
    + actualizarRecepcionCompletada(recepcion: Recepcion)
  }

  class NotificadorInventarioB <<ConcreteObserver>> {
    --
    + actualizarRecepcionCompletada(recepcion: Recepcion)
  }

  class ActualizadorEstadoOrdenCompra <<ConcreteObserver>> {
    --
    + actualizarRecepcionCompletada(recepcion: Recepcion)
  }

  interface ServicioInventarioB <<interface>> {
    --
    + notificarMovimiento()
  }

  class OrdenCompra {
    --
    + cambiarEstado()
  }
}

package "Flujo B: Facturación y Retenciones" {

  class FacturaProveedor <<Subject>> {
    - observadores: List<ObservadorFacturaProveedor>
    --
    + validarFactura()
    + calcularTotal()
    + guardar(estado: pendiente_retencion)
    + actualizarDatosRetencion()
    + agregarObservador(obs: ObservadorFacturaProveedor)
    + eliminarObservador(obs: ObservadorFacturaProveedor)
    + notificarObservadores()
  }

  interface ObservadorFacturaProveedor <<Observer>> {
    --
    + actualizarFacturaPendienteRetencion(factura: FacturaProveedor)
  }

  class EnviadorRetencionModuloD <<ConcreteObserver>> {
    --
    + actualizarFacturaPendienteRetencion(factura: FacturaProveedor)
  }

  class GeneradorCuentaPorPagarAutomatica <<ConcreteObserver>> {
    --
    + actualizarFacturaPendienteRetencion(factura: FacturaProveedor)
  }

  interface ServicioImpuestosD <<interface>> {
    --
    + enviarFacturaParaRetencion()
  }

  class CuentaPorPagar {
    --
    + guardar()
  }
}

note as Beneficios
  Beneficios del patrón en el Módulo C

  - Bajo acoplamiento entre Subject y Observer.
  - Automatización de procesos posteriores.
  - Nuevos observadores pueden agregarse
    sin modificar el Subject.
  - Mejor separación de responsabilidades.
  - Integración más limpia con Módulo B y Módulo D.
end note
